# РОССЕТИ — Кубаньэнерго · Реестр абонентов

Мобильное веб-приложение для поиска по реестрам абонентов электросетей. Код интерфейса — обычные HTML, CSS и JavaScript. База данных и сборка для рабочего запуска не нужны.

## Как работает

1. В общей публичной папке Яндекс Диска создаются папки предприятий электрических сетей. Их имена не зашиты в интерфейс.
2. В каждую папку помещаются `.xlsx`, `.xls`, `.xlsm` или `.csv` реестры. Файлы должны лежать непосредственно в выбранной папке предприятия. Макросы не исполняются.
3. В настройках сотрудник выбирает только предприятие электрических сетей. Приложение само открывает самый недавно изменённый Excel в этой папке. Файл **«Потребление»** зарезервирован для следующего этапа и полностью исключён из поиска абонентов, независимо от даты изменения. Регистр букв и расширение не важны; варианты вроде `Потребление_сентябрь.xlsx` также пропускаются. Если в папке только «Потребление», показывается сообщение, что реестр не найден. Служебные файлы Excel `~$…` пропускаются. При обновлении и следующем входе список читается заново, поэтому новый файл с другим именем тоже будет найден.
4. Обычная шапка с однозначно определёнными ПУ и ЛС принимается автоматически. Для неоднозначной структуры или пропущенных листов предлагается проверить столбцы. Подтверждённое сопоставление запоминается для предприятия и такой же шапки.
5. Ищет по ПУ, ЛС или адресу. По номерам по умолчанию используется точное совпадение, при необходимости — поиск по части. Все совпадения сохраняются, в том числе несколько строк одного ЛС.
6. Карточка показывает все значения исходной строки, названия столбцов, лист и номер строки. Пустые поля можно раскрыть отдельно.

Excel читается в Web Worker на устройстве. На сервер он не загружается. Сервер Амверы только передаёт файл с Яндекс Диска в браузер. Данные абонентов не записываются в localStorage, IndexedDB, серверную БД или репозиторий; в браузере сохраняются выбор предприятия, сведения о файле и сопоставление столбцов. При каждом новом посещении реестр скачивается заново. Кнопка обновления получает свежую версию в текущем сеансе.

Сведения в демонстрационном режиме полностью вымышлены. Для проверки без подключения Диска нажмите «Посмотреть пример», затем `ПУ 00123456` или `ЛС 00000001001` (у последнего две записи).

## Размещение на Амвере — основной вариант

В корне уже есть `amvera.yml`: Node.js 22, порт 3000, запуск `server.mjs`. Производственный сервер использует только встроенные модули Node.js. Установка npm-пакетов и сборка не требуются; Excel-библиотека уже находится в `public/vendor`.

1. Подключите этот репозиторий к приложению Амверы, ветка `main`.
2. В переменных приложения установите `YANDEX_PUBLIC_URL` — публичную ссылку на **корневую папку**. Пример формы ссылки: `https://disk.yandex.ru/d/ВАШ_КЛЮЧ`.
3. Перезапустите приложение. В настройках появится закреплённый источник и актуальный список предприятий из названий папок.
4. При необходимости ограничить сам сайт задайте одновременно `APP_USER` и `APP_PASSWORD`. Браузер покажет стандартный запрос имени и пароля; используйте HTTPS. Эти переменные не защищают публичную ссылку Яндекс Диска.

Ссылка задаётся **один раз в Амвере**, в разделе переменных/секретов приложения: имя `YANDEX_PUBLIC_URL`, значение — публичная ссылка на корневую папку. После сохранения переменной перезапустите приложение. На всех устройствах автоматически появится один источник; сотрудники выбирают только предприятие. Поля ввода ссылки в интерфейсе нет. Если переменная отсутствует или некорректна, показывается сообщение о неподключённом источнике. Сервер не принимает подмену корневой папки через параметры запроса. Приложение не требует OAuth-токена Яндекс Диска для публичных ресурсов.

Настоящие реестры с ФИО, адресами и телефонами не добавляйте в публичный GitHub. Публичная папка Диска доступна любому, кто получил её ссылку; пароль сайта не меняет доступность самого источника. Если реестр должен быть закрытым, требуется отдельная схема с закрытым Диском и серверной авторизацией.

## Можно ли без сервера — GitHub Pages

Да, поиск по Excel полностью работает в статическом браузерном приложении. Для проверки файла используйте «Настройки → Excel на устройстве». При открытии файла с устройства после перезагрузки страницы его нужно выбрать заново.

Для подключения Диска из статического сайта укажите `publicUrl` в `public/config.js`. Весь каталог `public/` можно разместить на любом HTTPS-хостинге статических файлов. Все адреса ресурсов относительные: сайт работает и под путём `/Web_abonent/`.

Для GitHub Pages предусмотрен запускаемый вручную workflow `Deploy static site`. В репозитории: **Settings → Pages → Source → GitHub Actions**, затем **Actions → Deploy static site → Run workflow**. Публикуется только `public/`, без серверных файлов и реестров.

Ограничение: браузер должен разрешать получение метаданных и скачивание Excel с серверов Яндекса (CORS). Работу полного цикла с конкретной публичной папкой нужно проверить. Если скачивание заблокировано, приложение покажет понятное сообщение и предложит открыть Excel с устройства. Сервер на Амвере устраняет эту зависимость от браузерного CORS. Случайные сторонние CORS-прокси не используются.

Открывать `index.html` двойным щелчком через `file://` не следует: модули и Worker требуют HTTP(S). Это ограничение способа запуска, а не необходимость в мощном сервере.

## Ограничения формата

- До 40 МБ на файл, до 100 000 строк и 256 столбцов на лист.
- Читаются все листы, на которых найдена шапка ПУ или ЛС; причины пропуска остальных листов показываются явно.
- Поддерживается обычная шапка, многострочная шапка с объединёнными ячейками и узнаваемая структура «Расширенный список» 1С из примера. Другие варианты нужно проверить на исходном файле.
- Сохраняются текстовые ведущие нули и нули из числовой маски Excel. Числовые идентификаторы с 16 и более цифрами отклоняются: Excel мог округлить их ещё до загрузки в приложение. Храните такие номера в текстовом формате.
- Если в Excel уже потеряны ведущие нули или точность, приложение не может восстановить их по догадке.
- Формулы не пересчитываются: используются сохранённые в файле результаты. Перед выгрузкой формульного реестра пересчитайте и сохраните его в Excel.
- Файл с паролем необходимо предварительно сохранить без пароля. Поддерживается обычный файл Excel, не HTML-страница, переименованная в `.xls`.
- Приложение не осуществляет запись в Excel и не изменяет исходную папку.

## Локальный запуск и проверки

```bash
node server.mjs
# Открыть http://localhost:3000
```

Для разработчика:

```bash
npm ci
npm test
npm run dev
```

Проверки включают реальные операции кодирования/чтения тестовой книги XLSX, многоуровневые шапки, сохранение номеров, дубликаты, страницы результатов, 25 001 строку, чтение источника из окружения, исключение «Потребления» и ограничения серверных адресов. Тестовые записи вымышлены. Бенчмарк Node.js не является измерением скорости на конкретном телефоне.

Excel-библиотека: SheetJS CE 0.20.3, Apache-2.0; локальная копия из пакета `@e965/xlsx@0.20.3`, лицензия рядом с библиотекой. Во время эксплуатации CDN не нужен. Vite используется только для разработки.

## Состояние первой версии

Интерфейс, чтение Excel и программный адаптер Яндекс Диска реализованы. Корневая ссылка пользователя и исходный `.xlsx` не были предоставлены. До их получения реальное чтение пользовательской папки и распознавание оригинальной книги не считаются проверенными. Публикация в GitHub не означает запуск приложения на Амвере или включение GitHub Pages.
