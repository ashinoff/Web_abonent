# РОССЕТИ — Кубаньэнерго · Реестр абонентов

Мобильное веб-приложение для поиска по реестрам абонентов электросетей. Код интерфейса — обычные HTML, CSS и JavaScript. База данных и сборка для рабочего запуска не нужны.

## Как работает

1. В общей публичной папке Яндекс Диска создаются папки предприятий электрических сетей, а внутри каждого предприятия — папки РЭС. Имена обоих уровней читаются с Диска.
2. В папке **РЭС** используются **«Расширенный список»** (реестр), **«ПО»** (потребление; полное имя **«ПО по месячно»** также поддерживается) и **«прием»** (технический учёт). Для каждого поддерживаются `.xls` и `.xlsx`, регистр букв не важен; «приём» также допустим. При наличии обоих форматов выбирается более новый по дате изменения, при равной дате — XLSX. Копии с суффиксами не выбираются.
3. После выбора предприятия открывается список его РЭС; файлы на уровне предприятия игнорируются. После выбора РЭС загружается реестр, месячная книга индексируется в отдельном Worker, а книга приёма проверяется на успешное чтение. Раздел **Настройки → Подключение → Просмотр файлов** показывает фактические имена, даты, число записей и состояния чтения. Напротив каждого источника есть **«Выбрать вручную»**: можно назначить любой XLS/XLSX из списка файлов выбранной РЭС, независимо от имени, и повторить чтение. Сохранённый ручной выбор применяется при обновлении и следующем входе в ту же РЭС; можно вернуть автоматический выбор. Если файл исчез, показывается ошибка, без подмены другим файлом. Остальные файлы перечисляются в содержимом папки, но не скачиваются. Ошибка одного источника не подменяет его другим. При входе и обновлении перечитывается вся цепочка папок.
4. Обычная шапка с однозначно определёнными ПУ и ЛС принимается автоматически. Для неоднозначной структуры или пропущенных листов предлагается проверить столбцы. Сопоставление привязано к предприятию, РЭС и такой же шапке. Оба выбора сохраняются; при смене предприятия старая РЭС и данные сбрасываются. Если сохранённая папка исчезла, предлагается выбрать другую.
5. Ищет по ПУ, ЛС или адресу. По ПУ/ЛС всегда ищется введённый фрагмент, без переключателя. Одно совпадение показывается на главном экране без автоматического открытия модалки. Несколько совпадений открываются в отдельном окне; повторное нажатие «Найти» открывает его снова. Все исходные строки сохраняются, в том числе несколько точек одного ЛС.
6. Под быстрыми данными ПУ и ЛС в выдаче и карточке показана строка **«Коэф ТТ = …»**. Значение берётся из столбца «Коэффициент трансформации», при многоуровневой шапке предпочтение отдаётся разделу «Прибор учёта». Пустое значение отображается прочерком; ноль и исходное форматирование сохраняются. Карточка показывает все значения исходной строки, названия столбцов, лист и номер строки. Пустые поля можно раскрыть отдельно.

Кнопка **«Реестр ТП»** открывает список ТП из реестра с фильтром по названию. После выбора — список ПУ, ЛС и точек учёта. Поиск закреплён в шапке на обоих уровнях: в выбранной ТП он фильтрует ПУ, ЛС, точки учёта, наименования и адреса во всём списке, включая ещё не показанные строки. В шапке количество абонентов по уникальным номерам ПУ, без объединения разных ПУ одного ЛС; количество совпадений показано отдельно. Повторы ПУ объединяются внутри выбранной ТП; в карточке можно выбрать любую исходную строку этого ПУ. Строки без номера ПУ в число не входят: их количество показано отдельно, поиск по ЛС доступен. Крупные списки загружаются порциями по 100 ПУ; кнопка внизу справа возвращает к началу.

В быстрых данных и карточке показаны номер и наименование точки учёта (ТУ/Номер ТУСТЕК, с запасным полем «Номер ТУ»). Карточка из списка открывается поверх него и сохраняет место прокрутки. Свайп вправо или стрелка влево в карточке возвращают к родительскому списку. Из реестра выбранной ТП свайп вправо или стрелка влево возвращают к выбору ТП с прежним фильтром и местом прокрутки. Свайп вниз закрывает любую модалку: начинайте его на шапке или в начале прокручиваемого содержимого. Окно следует за пальцем; завершённый жест плавно уводит его с экрана, короткий возвращает на место. Учтена системная настройка уменьшения движения. Обычная прокрутка длинного списка остаётся доступной; крестик и Escape также работают.

Данные карточки разделены на блоки с мягкими оттенками: лицевой счёт и договор, точка учёта, адрес, подключение, прибор учёта, события, рассчитанные величины, характеристики ТТ и ТН. Неизвестные столбцы попадают в «Другие сведения», пустые поля раскрываются отдельно с теми же цветами. При копировании сохраняются полные исходные названия столбцов.

«Найти» оформлена приглушённым голубым, «Реестр ТП» — мягким зелёным, анализ потребления — мягким оранжевым. Кнопка «Анализ контура ТП» активна после успешного чтения месячной выгрузки.

Предприятие выбирается отдельной заметной кнопкой над поиском, РЭС — второй кнопкой под ней. Выбранные названия выделены тёмно-синим. Лишние вводные заголовки над поиском убраны.

В шапке четыре компактных индикатора: **Яндекс**, **Реестр**, **Потребление**, **Приём**. Файлы проверяются после выбора РЭС: серый — ещё не выбран источник, голубой пульсирующий — чтение, зелёный — готов, красный — отсутствует или ошибка. «Потребление» зелёное после распознавания месячного отчёта. «Приём» зелёный после чтения заполненной книги Excel, без расчёта баланса. Любой индикатор открывает настройки. При смене рабочей области данные и текущие расчёты очищаются.

Выбор предприятия, РЭС, настройки и анализ на мобильном занимают весь экран. Настройки разделены на вкладки «Подключение» и «Анализ». В карточке абонента кнопка анализа открывает историю потребления по ЛС.

Excel читается в Web Worker на устройстве. На сервер он не загружается. Сервер Амверы только передаёт файл с Яндекс Диска в браузер. Данные абонентов не записываются в localStorage, IndexedDB, серверную БД или репозиторий; в браузере сохраняются выбор предприятия и РЭС, сведения о файле и сопоставление столбцов. При каждом новом посещении оба файла скачиваются заново. Содержимое месячной книги после проверки чтения не сохраняется. Кнопка обновления получает свежую версию в текущем сеансе.

Сведения в демонстрационном режиме полностью вымышлены. Для проверки без подключения Диска нажмите «Посмотреть пример», затем `ПУ 00123456` или `ЛС 00000001001` (у последнего две записи).

## Размещение на Амвере — основной вариант

В корне уже есть `amvera.yml`: Node.js 22, порт 3000, запуск `server.mjs`. Производственный сервер использует только встроенные модули Node.js. Установка npm-пакетов и сборка не требуются; Excel-библиотека уже находится в `public/vendor`.

1. Подключите этот репозиторий к приложению Амверы, ветка `main`.
2. В переменных приложения установите `YANDEX_PUBLIC_URL` — публичную ссылку на **корневую папку**. Пример формы ссылки: `https://disk.yandex.ru/d/ВАШ_КЛЮЧ`.
3. Перезапустите приложение. На главном экране станет доступен выбор предприятий из названий папок; сведения об источнике находятся в настройках.
4. При необходимости ограничить сам сайт задайте одновременно `APP_USER` и `APP_PASSWORD`. Браузер покажет стандартный запрос имени и пароля; используйте HTTPS. Эти переменные не защищают публичную ссылку Яндекс Диска.

Ссылка задаётся **один раз в Амвере**, в разделе переменных/секретов приложения: имя `YANDEX_PUBLIC_URL`, значение — публичная ссылка на корневую папку. После сохранения переменной перезапустите приложение. На всех устройствах автоматически появится один источник; сотрудники выбирают предприятие и РЭС. Поля ввода ссылки в интерфейсе нет. Если переменная отсутствует или некорректна, показывается сообщение о неподключённом источнике. Сервер не принимает подмену корневой папки через параметры запроса. Приложение не требует OAuth-токена Яндекс Диска для публичных ресурсов.

Настоящие реестры с ФИО, адресами и телефонами не добавляйте в публичный GitHub. Публичная папка Диска доступна любому, кто получил её ссылку; пароль сайта не меняет доступность самого источника. Если реестр должен быть закрытым, требуется отдельная схема с закрытым Диском и серверной авторизацией.

## Можно ли без сервера — GitHub Pages

Да, поиск по Excel полностью работает в статическом браузерном приложении. Для проверки файла используйте «Настройки → Excel на устройстве». При открытии файла с устройства после перезагрузки страницы его нужно выбрать заново.

Для подключения Диска из статического сайта укажите `publicUrl` в `public/config.js`. Весь каталог `public/` можно разместить на любом HTTPS-хостинге статических файлов. Все адреса ресурсов относительные: сайт работает и под путём `/Web_abonent/`.

Для GitHub Pages предусмотрен запускаемый вручную workflow `Deploy static site`. В репозитории: **Settings → Pages → Source → GitHub Actions**, затем **Actions → Deploy static site → Run workflow**. Публикуется только `public/`, без серверных файлов и реестров.

Ограничение: браузер должен разрешать получение метаданных и скачивание Excel с серверов Яндекса (CORS). Работу полного цикла с конкретной публичной папкой нужно проверить. Если скачивание заблокировано, приложение покажет понятное сообщение и предложит открыть Excel с устройства. Сервер на Амвере устраняет эту зависимость от браузерного CORS. Случайные сторонние CORS-прокси не используются.

Открывать `index.html` двойным щелчком через `file://` не следует: модули и Worker требуют HTTP(S). Это ограничение способа запуска, а не необходимость в мощном сервере.

## Анализ потребления

- Индивидуально анализируется сумма всех точек **ЛС в выбранной РЭС**, с запасным сопоставлением по «Лицевой счет СТЕК». Объём договора не присваивается каждому ПУ. Сравнения с другими потребителями и групповые поправки здесь отключены.
- Контур ТП строится по строкам файла потребления с данной ТП; один ЛС внутри контура учитывается один раз. Сравнения ограничены потребителями **выбранной ТП**. Из контура можно открыть подробности ЛС, затем вернуться стрелкой или свайпом вправо.
- Показаны флаги, баллы, базовый уровень, ориентировочная оценка отклонения и рекомендации. На графике: исходный ряд, пропуски, практические нули, база, точка изменения, а в контуре — медиана группы в карточке потребителя. Есть выбор месяца, масштаб, сдвиг окна, весь период и сглаживание за 3/6 месяцев. Масштаб и сглаживание не меняют расчёт.
- Годы берутся из периода в заголовке (например, Июнь 2024 — Август 2026). При отсутствии года, нарушении порядка или несовпадении периода выводится ошибка. Итоговый столбец не включается в ряд. Пустая ячейка не равна нулю; если хотя бы одна точка ЛС не заполнена, месячная сумма ЛС неизвестна. Для ТП сумма доступна только за полностью заполненные месяцы.
- Точные повторы одной точки/тарифной зоны исключаются с уведомлением. Разные значения повторённой точки/зоны блокируют анализ до исправления выгрузки. Разные тарифные зоны суммируются. Строки без номера точки не объединяются по догадке.
- Коэффициент ТТ повторно к готовому полезному отпуску не применяется. Мощность для признаков берётся только при однозначном сопоставлении всех точек с реестром. Отрицательные корректировки остаются на графике и в итогах, но не участвуют в поиске аномалий.
- Перенесены параметры 18 признаков, их отключение, пять уровней чувствительности, пороги зон по баллам/объёму, семь условий дополнительного приоритета и сброс к стандарту. Суточные настройки сохранены, но текущий источник содержит месяцы: D1–D3 не исполняются. Балансовые S11/D3 ждут технического учёта.
- Книга **«прием.xls / .xlsx»** пока проверяется только на читаемость. В интерфейсе оставлен блок подключения приёма, в результате анализа — `incoming.status = awaiting-format`. Реальный небаланс, потери и сценарии его покрытия не рассчитываются до появления согласованного формата и алгоритма. Настройка допустимой доли потерь сохранена для этого этапа.
- Оценки исходной модели предназначены для приоритизации проверки; это не установленный объём небаланса или начисления. Интерфейс не делает выводов о причинах по одному профилю. Спидометров нет.

Рядом с **«Коэф ТТ»** в краткой и полной карточке есть временный калькулятор: `(фактические показания − «Показания с квитанции показания») × Коэф ТТ`. Круглая галочка заменяет ввод рассчитанными кВт·ч, крестик очищает поле. Проверяются десятичная запятая, отсутствующие исходные данные и коэффициент; отрицательная разность показывается с пояснением. Ничего не записывается в книгу или хранилище браузера.

## Ограничения формата

- До 40 МБ на файл, до 100 000 строк и 256 столбцов на лист.
- Читаются все листы, на которых найдена шапка ПУ или ЛС; причины пропуска остальных листов показываются явно.
- Поддерживается обычная шапка, многострочная шапка с объединёнными ячейками и узнаваемая структура «Расширенный список» 1С из примера. Другие варианты нужно проверить на исходном файле.
- Сохраняются текстовые ведущие нули и нули из числовой маски Excel. Числовые идентификаторы с 16 и более цифрами отклоняются: Excel мог округлить их ещё до загрузки в приложение. Храните такие номера в текстовом формате.
- Если в Excel уже потеряны ведущие нули или точность, приложение не может восстановить их по догадке.
- Формулы не пересчитываются: используются сохранённые в файле результаты. Перед выгрузкой формульного реестра пересчитайте и сохраните его в Excel.
- Файл с паролем необходимо предварительно сохранить без пароля. Поддерживается обычный файл Excel, не HTML-страница, переименованная в `.xls`.
- Приложение не осуществляет запись в Excel и не изменяет исходную папку.

## Локальный запуск и проверки

```bash
node server.mjs
# Открыть http://localhost:3000
```

Для разработчика:

```bash
npm ci
npm test
npm run dev
```

`npm test`: проверяются обе книги XLS/XLSX, 27 месяцев с переходами годов, пропуски и нули, ведущие нули ЛС, сопоставление СТЕК, дубли точек, независимость индивидуального анализа от соседей, разделение объёмов по ТП, калибровки, калькулятор показаний и прежний поиск по 25 001 строке. Данные вымышлены. Исходное ядро дополнительно сравнено с пользовательским анализатором v4.4 на 20 профилях за 84 месяца в трёх калибровках. Скорость в Node.js не является измерением на телефоне.

Excel-библиотека: SheetJS CE 0.20.3, Apache-2.0; локальная копия из пакета `@e965/xlsx@0.20.3`, лицензия рядом с библиотекой. Во время эксплуатации CDN не нужен. Vite используется только для разработки.

## Состояние первой версии

Интерфейс, чтение Excel и программный адаптер Яндекс Диска реализованы. Корневая ссылка пользователя и исходный `.xls` не были предоставлены. До их получения реальное чтение пользовательской папки и распознавание оригинальной книги не считаются проверенными. Публикация в GitHub не означает запуск приложения на Амвере или включение GitHub Pages.

Официальная документация: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Node.js на Амвере](https://docs.amvera.ru/applications/environments/nodejs-server.html), [REST API Яндекс Диска](https://yandex.ru/dev/disk/rest/), [SheetJS](https://docs.sheetjs.com/docs/getting-started/installation/standalone/).
